# Dance-generation backend candidate — checked 2026-10-19

## Verdict

**EDGE is the strongest technical fit found, but it is not yet a fully rights-cleared, production-ready choice.** Unlike MoMask/MotionGPT-style text-to-motion, EDGE actually conditions motion on music embeddings and emits articulated dance motion. Its public reference implementation is old research code, and its feature frontend has a noncommercial-use license. The original checkpoint link has no separate weight license visible in the upstream README; a third-party Hugging Face reproduction declares MIT, which is not enough by itself to settle provenance/rights for the original weights. Treat it as a bounded personal/research candidate only after resolving those exact terms. It does not accept a beat grid or text instruction as an explicit conditioning channel.

## Six-plus primary-source checks

1. **Official project page** — [EDGE project page](https://edge-dance.github.io/) describes music-conditioned generation from Jukebox embeddings, joint-wise constraints, in-betweening and continuation. It supports “music to dance,” not text-to-motion, video rendering, or arbitrary pose editing.
2. **Authors' repository and setup** — [Stanford-TML/EDGE README](https://github.com/Stanford-TML/EDGE/blob/main/README.md) exposes the executable path: custom `.wav` input via `python test.py --music_dir ...`; `--save_motions` saves motion; conversion script exports FBX for Blender/retargeting. It explicitly calls itself research code that may not be maintained. Stated requirements: Linux recommended, Python 3.7+, PyTorch 1.12.1, CUDA 11.6, at least one 16-GB NVIDIA GPU (validated on one T4); two 5090s are not required for a first test.
3. **Authors' inference source** — [`test.py`](https://github.com/Stanford-TML/EDGE/blob/main/test.py) chooses Jukebox features by default, slices supplied WAVs into 2.5-second chunks, extracts music representations, runs `EDGE`, and passes the motion-save directory when requested. [`args.py`](https://github.com/Stanford-TML/EDGE/blob/main/args.py) defines music directory, output length, save-motions, cache and render flags. This is source evidence of actual audio conditioning and artifact-saving path, not proof of quality on our material.
4. **Code license** — [upstream LICENSE](https://github.com/Stanford-TML/EDGE/blob/main/LICENSE) is MIT for repository software. The README points to a Google Drive checkpoint but does not specify a separate checkpoint license there; code license should not be silently treated as a weight grant.
5. **Checkpoint mirror** — third-party [Motius EDGE/AIST++ model card](https://huggingface.co/ZeyuLing/Motius-EDGE-AISTPP) offers a 49.5M-parameter checkpoint and declares MIT on that card; it describes itself as a reproduction of the released AIST++ network, not the original authors' distribution. It documents outputs as `joints: (frames,24,3)` Y-up metres, `edge_motion: (frames,151)`, and `motion_135: (frames,135)`, native 30 fps. EDGE-151 is 4 contact channels + root position + 24 SMPL local 6D rotations. This representation is not the current prototype's joint-name JSON and needs a deterministic SMPL-24-to-rig adapter.
6. **Paper** — [CVPR 2023 paper](https://openaccess.thecvf.com/content/CVPR2023/papers/Tseng_EDGE_Editable_Dance_Generation_From_Music_CVPR_2023_paper.pdf) describes music-conditioned dance and editing constraints; the paper's music alignment comes from learned audio features and evaluation, not a user-supplied beat/time-signature control input.
7. **Frontend license and supply chain** — EDGE's required Jukebox frontend is [`openai/jukebox`](https://github.com/openai/jukebox), now archived; its [LICENSE](https://github.com/openai/jukebox/blob/master/LICENSE) restricts software and created content to noncommercial purposes. The third-party model card says the EDGE checkpoint does not include Jukebox VQ-VAE/prior files; `jukemirlib` downloads them on first use. Therefore even the MIT-labelled checkpoint route inherits a material frontend restriction unless embeddings are independently supplied under a compatible, cleared route.
8. **Training-data terms** — official [AIST++ download page](https://google.github.io/aistplusplus_dataset/download.html) requires acceptance of the AIST Dance Video Database terms before downloading video/music. The official [dataset facts page](https://google.github.io/aistplusplus_dataset/factsfigures.html) says annotations are CC BY 4.0. This is separate from EDGE code/weights and does not license arbitrary user songs.

## Bounded future test and connection to our compiler

After rights review, run one short (8–12 s) licensed/owned music input through the published checkpoint on one Linux GPU; preserve input hash/rights note, code and checkpoint revisions/hashes, Jukebox frontend files/hashes, seed, raw saved `.pkl`, extracted motion array, logs, and any FBX. Do not render until array shape, finiteness, monotonic 30-fps timebase, root continuity, contact channels and all SMPL bone lengths pass host checks. Keep generated output as `edge_motion.npz` or an unmodified pickle plus a small manifest; write a separate adapter exporting `{time, joints, contacts}` in the compiler's x-lateral/y-forward/z-up coordinates. Convert Y-up explicitly; never overwrite source arrays. Confirm the four contact-channel ordering in the decoder before mapping heel/toe channels into provisional per-foot flags, and verify them against trajectories. Retarget SMPL-24 motion to the prototype's proportions through constrained IK, then test contact sliding and segment lengths before any audition.

Compare against the procedural phrase shelf on the same short track with a fixed camera and blind A/B. Record mechanical screeners separately from human groove/phrasing preference. A pass would establish a usable local candidate for that clip and pipeline only, not dance authenticity, generalization, beat-grid control, legal clearance of all training data, or artistic quality.
