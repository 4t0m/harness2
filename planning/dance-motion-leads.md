# Dance motion: source-backed next leads

Archive searches covered `dance choreography`, `motion primitives`, `animation retarget`, `controllable character`, `motion matching`, `local animation tools`, plus `motion capture`, `Blender animation`, `pose retargeting`, `dance generation`, and related terms. The first set mostly returned one choreography post, one closed avatar product, irrelevant matches, or no exact lexical match; that is an archive retrieval result, not evidence that tools or research do not exist. Saved posts are leads, not capability or quality verification.

## 1. Grow a small reusable phrase shelf, then let the planner sequence it

The most aligned next POC is a tiny catalog of 6–10 short, model-independent motion phrases with explicit entry/exit stance, beat duration, support-foot/contact events, root envelope, tags and provenance. Have a small local model choose/order phrases for a fixed 8–16-beat score; host code checks transitions, contacts and timing; run short fixed-camera A/B auditions and retain timestamped human keep/change labels. This continues the existing D0–D2 ladder without asking a planner to invent per-frame motion.

For implementation/asset handling, [Fairmotion](https://github.com/facebookresearch/fairmotion) is a source-verifiable candidate: its repository describes tools to load, process and visualize motion-capture data and states BSD-3-Clause for the library. That license does **not** establish rights to any motion dataset loaded through it; qualify each clip's source and terms separately. Alternatively, keep the first shelf procedural/user-authored. The saved Kevin Ngo post describes a code-authored 2D animation transferred into Blender while preserving choreography ([tweet](https://x.com/kevin_t_ngo/status/2108582192481992922)); this is inspiration for a compact score/pose representation, not a reproducible repo or proof of motion fidelity. Blender's [Actions documentation](https://docs.blender.org/manual/en/4.3/animation/actions.html) confirms keyframed properties are stored as Actions and can be managed/reused; it supports a practical clip container, not automatic retargeting.

## 2. Make audition feedback the next optimization target

With one unchanged phrase set and renderer, compare two planner conditions (fixed symbolic rules vs. local-model selection) across several short rhythmic briefs. Blind/randomize candidate order; ask the user for keep/both/neither and timestamped change notes. Report mechanical checks separately from taste, and measure whether a correction preserves accepted neighboring spans. This turns subjective preference into an explicit, inspectable signal without training a universal “good dance” score. The archive's [AIWarper post](https://x.com/AIWarper/status/2061824522773496227) suggests reference-video-driven dance mapping, but names hosted Seedance/Google services and supplies no motion export, reproducible interface or rights information. Keep that as an optional human-supplied reference/audition stimulus, not a dependency or asset source.

## 3. Defer generated motion until a specific gap is measured

Only after the shelf shows a repeated missing capability (for example, a turn that exits on a specified foot), test one motion-generation/retarget backend against that exact phrase contract. Require saved raw output, rig/coordinate contract, source and model license, and the same independent contact/continuity checks. Archive searches for `motion matching` and `animation retarget` did not surface a strong reusable implementation; do not infer the approach is unavailable. A saved Seedance dance-reference post ([tweet](https://x.com/Mayz1169/status/2103139749540339890)) is a closed image/video result and does not establish editable joints, retargetable motion, provenance or usage rights.

## Recommended next POC

Implement the phrase shelf and local-plan-to-host-compiler path first, using only procedural or explicitly owned/licensed clips. Add 2–3 contrasting phrases, compare fixed-rule and local-model sequencing on the same held-out briefs, then run a small blind audition. Unknowns: which phrase tags actually help retrieval, whether user feedback is stable across music/context, asset retarget cost, and whether a chosen generator returns suitable joint tracks. No dance authenticity, biomechanics, or artistic-quality claim follows from passing the existing screeners.
