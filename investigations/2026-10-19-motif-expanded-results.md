# Expanded motif-score rejections — investigation plan

## Frame and context

The probe should accept any 16-pair expanded plan representing the same 32 supported AABA intents as the compact interface. The live local run is showing repeated expanded compiler rejections while compact outputs often compile. This matters because a strict-grammar or runner defect would invalidate a representation comparison. The score compiler and its exhaustive 32-intent tests were frozen before this run; there has been no correction or source change in response to the live failures. Recent related history contains the original phrase shelf (`8dd5b14`), while this score/probe trial is new and uncommitted.

## Hypotheses and distinguishing checks

1. **Compiler falsely rejects legal expanded scores.** Recreate every intent with the host's declared `rise, motif, motif, settle` grammar, compile both forms, compare canonical intent/sequence hashes, and independently inspect rejected raw pairs. Confirmation would be a rejected raw output satisfying exact AABA grammar or a canonical generated expanded score failing. Rule out if all canonical scores pass and each rejected raw has a concrete grammar violation.
2. **The expanded response schema or prompt steers the model into structurally wrong identifiers/pair lengths.** Inspect `SCHEMAS.expanded`, exact first and repair contents and compiler errors for each local case. Count object shape, pair count/length, identifier validity, and JSON completeness separately. Confirmation would be failures concentrated in schema-permitted but invalid position/identifier choices or malformed arrays. Rule out if shape and identifiers conform while only cross-section motif/accent relations fail.
3. **The model follows local pair format but loses AABA or section accent consistency.** Decode all complete 16-pair outputs into four sections and compare motif order and accent uniformity with the public contract. Confirmation would be full well-formed arrays with wrong section content. Rule out if outputs fail before these semantic relations can be tested.
4. **Runner/receipt or feedback path misattributes rejection.** Replay each saved `content` through the frozen compiler, compare exact exception strings and `compiled` flags, confirm repair follows only a rejected first attempt, and verify messages contain the original brief plus generic public error without host expected values. Confirmation would be a replay mismatch or leaked expected mapping. Rule out if all saved rows replay and message lineage matches.

## Planned evidence and boundary

Use only saved `evidence/dance-motif-model-v1.json`, the frozen source files, and offline compiler calls; do not call providers or modify trial data. Read source digests and metadata, replay first and repaired outputs, then classify failures by structural shape, identifier, AABA motif sequence, accent uniformity, and brief accuracy. Compare hosted rows when the run completes. These are observed fixtures, so any prompt/schema explanation remains diagnostic, not a causal or held-out performance claim.

## Findings from completed v1 receipt

The receipt is complete: 64 model/case/condition slots, 84 calls, no provider failures. All six recorded source SHA-256 values match current bytes. Every call is bound to one result, and all stopped raw contents replay through the recorded compact or expanded compiler to the same `compiled`, intent, motion receipt, brief-violation list, and exact compiler error. Each of four models has all eight cases in each condition. The two conditions are interleaved, with case order reversed for alternating models. Prompt/correction lineage matches the saved system and request strings; the correction includes the actual previous response plus a generic host grammar rejection, never fixture `expected`. No compiled-but-brief-wrong output received a correction. Maximum message content is 1,454 UTF-8 bytes, below the 10,000-byte cap. Total recorded usage is 22,715 input and 5,414 output tokens; hosted cost sums to $0.002284306, matching the receipt within floating-point representation.

**Hypothesis 1, false compiler rejection: ruled out for this fixture set.** Independently constructed all 32 compact intents and their 16-pair expansions (two motifs × 16 four-accent vectors); all pairs compiled and verified to identical result dictionaries. Every rejected raw output has a concrete grammar violation. This does not prove the compiler correct for arbitrary JSON, but it establishes the advertised supported choice space in this experiment.

**Hypothesis 2, structural/schema failure: partially supported, but not the main cause.** All 32 local expanded first/final outputs are parseable 16-pair arrays, with strings drawn from the schema's single six-value union. The schema allows any of `rise/sway/pulse/settle/soft/clear` in either pair position and does not encode pair-position, four-move, section-accent, or AABA constraints. One E2B repaired answer uses `pulse` as the variation in all pairs: accepted by that union enum but rejected by the compiler. The other local failures use legal move and variation identifiers yet violate the public grammar. The receipt cannot establish whether constrained decoding was applied internally; it only shows outputs compatible with this broad schema.

**Hypothesis 3, repeated-structure failure: strongly supported.** E2B expanded was 0/8 first and 0/8 final; Qwen local was likewise 0/8 and 0/8. In E2B's first outputs, all eight violate the AABA motif sequence, three also break the four-move section layout and three also break accent uniformity. In its final outputs, all eight still violate AABA; three break layout, one accent uniformity, and one has an invalid variation field. Qwen local first and final outputs each show six AABA violations, four layout violations, and three accent-uniformity violations (overlapping counts). A concrete E2B first output for `motif_plain_language_sway` has valid `rise,sway,sway,settle` sections but repeats `sway` in B rather than switching to `pulse`. The Qwen local `motif_direct_pulse_all_clear` first and repair have all four sections on `pulse`, again omitting the contrasting B. Several repaired strings repeat the first answer exactly, so the generic correction did not resolve those violations.

**Hypothesis 4, runner or feedback misattribution: ruled out on saved data.** Source hashes, raw replay, call/result binding, and exact repair-message reconstruction all agree. Repaired outputs occur only after a stopped, uncompiled first response. The scorer's expected intents remain offline. The broad schema is a contract weakness, while the observed AABA and section errors are actual model outputs under that contract; no parser false-negative or leaked oracle explains the local failures.

Hosted comparison narrows a blanket model-inability claim: hosted Gemma expanded compiled and matched the brief in all 8 cases; hosted Qwen compiled/matched 4/8, with four failed cases showing full `rise,motif,motif,settle` sections and uniform accents but wrong AABA motif placement. Both hosted compact arms were 8/8. Local compact arms were E2B 6/8 and Qwen 8/8 brief-correct, both 8/8 structurally compiled. These results are a fixed observed-case representation comparison, not causal isolation of schema versus prompt effects or held-out quality. In compact mode the host expands one motif choice plus four accents into 321 poses; no model generated or validated 321 joint frames. A bounded next diagnostic would hold cases/models fixed and vary only the expanded schema's positional constraints or a more explicit four-section prompt, with a fresh test set for a generalization claim. No source or live trial change is recommended from v1 alone.
